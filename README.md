# Magid Bid Normalizer prototype

For code ownership, invariants, verification commands, and remaining technical debt, see
[Maintaining the prototype](docs/maintaining-the-prototype.md). The sections below include historical implementation notes.

For repeatable checks, start with [Verification setup and acceptance checklist](docs/verification.md).
Run `npm run verify` after supplying the private test fixtures. GitHub runs the
explicitly smaller `npm run verify:core` profile; it does not certify full acceptance.

A private, browser-session prototype: upload an Excel proposal, inspect source-backed candidate records, accept/edit/blank fields, decide item boundaries and extra columns, then download the original Magid template filled with reviewed values. Original workbook bytes and review decisions remain in the browser. AI starts automatically after upload; bounded source-cell evidence is sent through the authenticated server to the configured provider (OpenAI or Google Gemini); neither the app nor the browser saves proposal history. Closing/reloading the tab loses the session.

## Current implementation

React/Vinext frontend with shadcn controls; a cancelable Web Worker parses OOXML with fflate and xmldom. A fixed template is the only hosted workbook. Deterministic rules recognize the five supplied sample layouts; other layouts use reviewer-configured column mapping. Source sheets, cells, formulas and hidden-row metadata remain available for inspection. Every exported value requires a verified session decision: a deterministic source rule, a grounded separate evaluation, or an explicit reviewer action. Group review previews the complete scope and supports exceptions by search/individual decisions. Split/merge produce fresh pending candidates.

Excel export edits only the identification worksheet XML. A:M headers and styles are retained; approved columns append at N. Original other worksheet bytes are unchanged. Unused default numbers/question marks are removed. Text is inline-string data, never formulas. Annual usage and pack-count bounds are checked. Generated workbook values are parsed again and compared before download.

Limits: 20 MiB upload; 200 MiB expanded ZIP; 10,000 members; 50 sheets; 1 million populated cells; 2,000 output rows. Macros and external links never run. XML DTD/entities and encrypted/legacy containers fail clearly. Parsing timeout is 60 seconds with cancellation. Session expiration is 60 minutes idle or 8 hours absolute; successful download adds a 15-minute grace window, with an explicit continue-review option.

## Remaining before the complete AI prototype is accepted

The AI extraction service is implemented using OpenAI Responses, a pinned GPT-5.4 Mini model, strict JSON output and request-local source checks. The server-side OPENAI_API_KEY secret is installed. The first live request reached an API quota/rate limit; successful live extraction remains pending account credits. Do not put API keys in client code. The service uses a fixed tool-free task, bounded source scopes, 90-second timeouts and at most one transient-error retry. It checks quoted source evidence, raw identity/size tokens, manufacturer namespace, annual quantity period, units, item count and pending-only review states. Model output cannot assert approvals. The controller can accept eligible source-backed values only after a separate evaluation and independent source checks. Client checks repeat against the untouched original workbook and bind output to source digest/scope; approved human values are preserved. Source scopes are enriched in atomic ten-record batches; unknown layouts can propose boundaries from a selected row region. Whole-workbook interpretation and live AI acceptance remain pending; canonical final readiness is enforced at export.

The existing v1.1 Python canonical schema/validator package remains authoritative for the complete pipeline. The UI projects its reviewed-field model into canonical v1.1 records and checks them against the original workbook at export. Export now enforces full canonical final readiness; this does not establish full end-to-end AI acceptance. Coverage has cell classifications, source roles, exact-scope reasons and validated sheet-layout decisions, with automatic rules for recognized layouts and manual decisions for exceptions. Account-specific provider retention verification, field-label acceptance, authenticated multi-user review and full end-to-end acceptance must be completed and tested before client use. AI application is guarded by source/session and review revisions; an edited proposal discards stale AI results. No persistent memory, uploads, audit database, catalog enrichment or inventory matching are implemented.

`node tests/ai.test.mjs` verifies source grounding, rejection of fake/missing/altered evidence, lost leading zeros, forbidden approvals, namespace/annual-period/pack rules, occurrence preservation, human-edit preservation, response scope binding, provider failures, retries, request bounds and all five original layout scopes. Provider calls are mocked in these tests; they do not certify live credential/model access.

Selected cell content is sent to OpenAI only on an explicit AI action. Requests use store:false and no tools, file uploads, conversation threads or background jobs. This disables response application-state storage; provider abuse monitoring and prompt-cache retention are separate and may still apply. User-visible disclosure appears before running AI. See [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) and [API data controls](https://developers.openai.com/api/docs/guides/your-data).

## Canonical v1.1 integration

`lib/canonical/reference/` preserves the supplied v1.1 schema, Python validator, synthetic fixture and reference tests. `validator.mjs` ports its shape and semantic checks to the browser; `bridge.mjs` projects all twelve fields, full cell evidence inventory, typed identifiers, quantities, units, packaging and extensions. Review actions populate a separate, transient controller registry. UI/model status flags do not mint approvals; signatures bind approval to the exact value, source, boundaries and relevant unit/manufacturer dependencies. Reviewer edits without source evidence are explicitly labeled reviewer assertions. Blank means accepted unknown, never a fabricated absence or default. Unfamiliar units retain their spelling through OTHER+label.

Before Excel writing, the source bytes are hashed again and independently reparsed, canonical final-readiness validation runs against that inspection, and stale-session/review checks reject changed state. Unverified formulas (including empty shared-formula expressions), nonannual accepted usage, incompatible pack/container units and invalid typed scalars block export. Shared formula placeholders are marked `[unresolved shared formula]`; this marker is metadata, not a calculated expression. The original workbook is never executed.

The bridge projects only current cell classifications and sheet-layout approvals into canonical regions and evidence roles. Unreviewed or stale coverage remains unresolved. Export requires every source cell and sheet layout to have a current decision; a global confirmation cannot bypass these checks. `final:true` is now the production export gate. `lib/canonical/export.mjs` shares the checks between the Export screen and download, requires current controller approvals and coverage, and reparses the immutable original bytes before writing. The original template fields must contain a source-backed description, bid sequence, customer reference or manufacturer part; a stock-code extension alone is insufficient under the authoritative v1.1 policy. Explicitly excluded items retain lineage and source evidence but have no selected field candidates or exported extension values. V1 uses the transient session reviewer inside the private app; named multi-user attribution and whole-workbook human acceptance remain pending. Formula evaluation remains unavailable. No persistent audit or proposal storage is added.

`node --test tests/canonical.test.mjs` compares JavaScript with Python on 50 draft/final cases, tests controller separation and invalidation, and validates drafts from all five original workbooks with both implementations. `python -m unittest test_validator test_hardening` in the reference directory runs 37 original tests. Synthetic contexts in those tests are never used by the app.

## Coverage, dependencies and stale decisions

Coverage includes every parser-inventoried cell across all sheets, hidden rows/sheets and formula caches. Reviewers select up to 100 visible cells, inspect a frozen preview, choose item/header/context/excluded and a source role, and provide a reason. Item classifications require included item associations. Included anchors cannot be excluded or reclassified as context; excluded cells cannot supply output values. Each sheet layout requires complete current cell coverage and its own rationale. Supplier quote, alternate, historical and catalog evidence cannot become selected customer product facts.

Coverage signatures bind cell values/type/formula, hidden metadata, item associations and per-item revision epochs. Changing an item reopens its related coverage and sheet-layout approval; unrelated cells retain their decisions. A reverted edit cannot resurrect prior coverage. All mutations are session-only.

Dependencies include description→size/manufacturer/parts/quantity/unit/pack, manufacturer→parts, unit→quantity/pack and quantity↔pack interpretation. Value, evidence, quoted spans and source context changes reopen dependent accepted values and deliberate blanks. AI reconciliation may invalidate approvals but cannot create them. Additional-column approval binds its semantic definition; changed AI definitions require renewed column review.

Group previews freeze exact records. AI requests, bulk decisions and Excel downloads use browser-owned source/session/review/controller revision tokens. Stale responses are discarded before application, and export also rehashes/reparses original bytes before validation. Expired or replaced sessions cannot receive an older export error or completion state.

`tests/coverage.test.mjs` covers hidden/full inventories, final validation plus Excel readback on a synthetic reviewed case, stale atomic scope rejection, revision reversion, unrelated-cell preservation, excluded-source conflicts, quote contamination, dependency invalidation, AI reconciliation and async tokens. Actual Tesla inventory verifies all cells/sheets, including sheets outside proposed items; it is not a claim of human-labeled final gold coverage. Browser interaction and successful live AI remain unverified.

`node --test tests/source-acceptance.test.mjs` now exercises two analyst-checked Grainger occurrences (Sheet1 A4 and A6) from the original workbook through simulated reviewer decisions, current cell/layout coverage, canonical `final:true` validation, Excel export and readback. It verifies clean product wording, the original L/2L sizes, approved stock-code extensions, blank unsupported identifiers/annual usage/pack fields, and unchanged other template parts. A description edit and subsequent reversion must leave dependent fields and coverage unresolved. This is a deliberately scoped two-item fixture: all other original cells are explicitly excluded for this test only. Neither those exclusions nor the simulated decisions are human approvals, whole-workbook gold labels, successful live AI, browser acceptance, or whole-workbook production acceptance. Original workbooks and analyst-checked source fixtures remain outside the hosted repository; missing fixtures fail the test rather than silently skipping it.

`node --test tests/final-export.test.mjs` adds scoped real-workbook cases for Daikin (period-unknown quantity stays outside Annual Usage), Hyundai (repeated stock codes stay distinct; pair-per-box text is retained without conversion), Tesla (conflicting pack count deliberately blanked), and Berry (a reviewer-selected source heading supplies a coarse description; the customer stock code is not relabeled as a manufacturer part). The Grainger cases use the same production export helper. Tests require explicit simulated approvals and full source-cell classification, reject stale/unapproved values, source hash mismatches, unknown annual periods and identity-only extensions, and verify excluded malformed values do not leak into output. These scoped test exclusions are never real bid approvals. Browser upload/review/download and successful live AI still require acceptance testing.

## Gemini provider integration

`AI_PROVIDER=gemini` selects Google Gemini Generate Content; `GEMINI_API_KEY` is a server-only secret and `GEMINI_MODEL` defaults to gemini-3.8-flash. OpenAI remains supported through `AI_PROVIDER=openai`, `OPENAI_API_KEY` and `OPENAI_MODEL`. There is no automatic cross-provider fallback or client API key. Both adapters use the same bounded evidence, tool-free task, strict output/source checks, cancellation, retry policy and pending-only candidate application. Gemini uses the fixed Google endpoint and x-goog-api-key header with JSON response schema; refusals, truncated output and invalid credentials fail safely. Provider-aware UI notices explain that unpaid Gemini usage may be used for product improvement and human review; no store:false or zero-retention claim is made for Gemini. See https://ai.google.dev/gemini-api/terms and https://ai.google.dev/gemini-api/docs/generate-content/structured-output.

A synthetic live Gemini request on 2026-10-01 reached Google, which rejected the supplied credential as invalid. No original bid content was submitted. Successful live Gemini extraction remains pending a valid Google AI Studio API key; automated provider tests use mocked responses and do not certify model quota/access or real-bid accuracy.


## Temporary pipeline debug tab

`PIPELINE_DEBUG_ENABLED` in `lib/debug/trace.mjs` is the single switch for the tab, browser trace collection, parser progress, and server diagnostic response data. Set it to `false` and rebuild to disable the feature. No debug database, browser storage, console output or provider reasoning is collected. The existing review controller remains the approval authority.

The tab shows parsing/identification events, initial versus current item fields, original source evidence, candidate explanations and alternatives, planned Excel destinations, current canonical blockers, AI batch diagnostics, review changes, and export template/readback verification. Server diagnostics arrive with each completed batch response, not as a live stream from the provider. Batch results are labeled staged until all batches pass; failures discard them. No new pause/step execution controls or authority to bypass validation are introduced.

The trace is bounded to 400 events with 12,000-character detail previews, marked when truncated; canonical issue display is capped at 100. Initial item candidates are retained by reference for the session. Clear/new upload, existing expiration, and page close release debug state. It contains customer source content, like the rest of the temporary review session.

For complete removal, delete the `PipelineDebug` tab/button and debug hooks in `app/page.tsx`, `components/debug/`, debug CSS, and `lib/debug/`. Remove the optional observer calls/imports in the parser, AI service/route, and export helpers. Those observers do not feed pipeline decisions. `tests/debug.test.mjs` and the AI diagnostic test check disabled collection, memory bounds, observer failures, credential omission and unchanged Excel member contents (ZIP timestamps may vary).

## Exceptions-only processing

Upload runs deterministic extraction, a structured provider extraction, and a second provider call that evaluates the proposed fields against original cells. Evaluation uses supported/review/unsupported findings and source-backed missing-fact findings, without model confidence percentages or provider chain of thought. Every occurrence and proposed field must be returned exactly, with genuine original quotes. All batches finish before any AI result is committed; partial failure or stale scope blocks export. Final readiness requires evaluation completion in the app workflow.

Explicit Item # narratives and verified table rows receive system inclusion decisions. Visible nonformula linked item cells, known headers and recognized source context receive system coverage decisions; unknown regions, hidden content, formulas and missed Item # cells remain exceptions. System records do not fabricate human review events. Semantic acceptance uses a separately verified evaluated-v2 proof bound to exact field values and dependencies. Supplier lanes, conflicting alternatives, ambiguous pack relationships and stale decisions cannot receive this proof. Pack quantities currently remain conservatively subject to review. Unknown-layout boundaries still need a verified source rule or reviewer decision.

The default interface shows exceptions only; completed fields are collapsed and every output cell remains inspectable. Unsupported blanks need no approval. Useful extra columns still require human approval; exact source extra values can pass deterministic checks independently. Codes and ordering notes already preserved in the full narrative do not force redundant added columns. No persistent storage or AI BID SETUP population is added.

84 automated tests pass, including a real 31-item Grainger export/readback with controlled grounded evaluator responses and zero fabricated human field/row/layout approvals. Negative tests cover evaluator disagreement, missing facts, boundary concerns, invalid quotes, failed evaluation, supplier/formula/hidden evidence, missed source items, stale dependencies and changed source bytes. These tests establish pipeline behavior, not production model accuracy. Browser acceptance and live provider accuracy checks for this change remain pending.


## Request reliability and exception isolation

Provider extraction and independent evaluation use separate authenticated POST stages (`X-AI-Stage: extract|evaluate`). Each provider request has a 24-second deadline; the browser deadline is 28 seconds. Enrichment starts with three records per scope, reducing timed-out groups to single-item requests. Temporary per-user leases expire and cancel at 27 seconds; ownership IDs prevent a late request from unlocking a newer request. Completed stages stay only in the current browser session and resume on retry if source, current values and reviewer revision are unchanged. Nothing is saved to disk, browser storage or a database.

AI operation tokens exclude automatic controller bookkeeping, but retain source digest, session generation, genuine reviewer revision and synchronous run ownership. Export and human batch decisions retain strict controller revision checks. Recognized parser header context permits the Tesla pieces/UOM header; other product rows cannot serve as headers. Structural, occurrence and scope failures remain fatal. Invalid base-field suggestions are omitted and unresolved original fields become explicit exceptions, including otherwise empty fields. A nonempty original value independently verified by a deterministic source rule stays automatic when an untrusted rewrite is rejected. Invalid independent field findings become review verdicts with verified original evidence. Invalid missing-information evidence remains fatal.

An item counts as automatic only if every required field disposition is automatic. Item completion is shown only after AI and source coverage checks finish. Export generates and validates the workbook before exposing a real Save Excel file link. Its blob remains available in the temporary session, with cleanup after changes, replacement or expiry. Receipt is never asserted merely from generation or a click.

Regression tests cover retry cache isolation, changed reviewer decisions, automatic proof bookkeeping, HTML timeout responses, field quarantine, evaluator omissions, actual Tesla headers, single-stage provider calls and accurate automatic-item counts.

Source scopes exclude unrelated product narratives. Gemini 3 stages explicitly use the documented `thinkingLevel: low` setting to limit latency (https://ai.google.dev/gemini-api/docs/generate-content/thinking); no thought summaries are requested. Incomplete multi-item responses also trigger scope reduction. This changes request cost/latency, not approval requirements.
